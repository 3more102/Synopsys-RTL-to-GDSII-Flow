# Quality Gates and Release Contracts

This repository separates three different concepts that must not be conflated:

1. **Tool execution success** — the EDA process returned exit code 0.
2. **Flow-quality evidence** — timing/formal/artifact checks prove the configured engineering acceptance criteria.
3. **Foundry signoff** — qualified DRC/LVS/extraction/EM/IR methodology has actually been executed with approved decks and models.

## Stage runtime evidence

`scripts/common/run_stage.sh` writes one immutable JSON record per invocation under `reports/runtime/` and updates `<stage>.latest.json`. It records tool path, script, Git commit/dirty state, timestamps, duration and process exit code. A separate `<stage>_runner.status` records only process execution health; it does **not** override the engineering status generated by Tcl/report analysis.

A per-stage lock under `work/locks/` prevents concurrent writers from modifying the same stage/database accidentally.

## QoR summary

`python/generate_summary.py` extracts only metrics it can prove from existing reports. Missing values stay `N/A`; they are never manufactured. It now attempts to collect WNS, TNS, setup/hold violation counts, area, utilization, cell count, power, congestion, DRC count and measured stage runtime.

## Release contract

`config/stage_contracts.json` defines the machine-readable artifact/status contract. Run:

```bash
make verify
```

Default `FLOW_RELEASE` mode requires the post-route netlist, final SDC, SPEF and GDS plus successful synthesis, Formality, extraction, setup STA, hold STA and GDS-generation evidence. DRC/LVS remain advisory because a generic public flow cannot fabricate foundry-qualified decks.

To require SDF as a release artifact:

```bash
REQUIRE_SDF=1 make verify
```

To enforce qualified DRC/LVS evidence as well:

```bash
STRICT_SIGNOFF=1 make verify
```

`STRICT_SIGNOFF=1` is expected to fail until real foundry/PDK DRC and LVS integrations write `PASS` status evidence. That failure is intentional.

## Static validation without licenses

```bash
make static
```

This checks shell syntax, Python syntax, JSON validity, Makefile parsing, Tcl/SDC lexical completeness (when `tclsh` is available), and unresolved merge markers. GitHub Actions runs the same check without requiring Synopsys licenses.

## Release target

```bash
make release
```

Builds final deliverables, runs release verification, and creates a reproducibility snapshot. Use `make all` for the normal complete flow; it finishes through the `release` target.

## Interpretation

A `FLOW_RELEASE PASS` means the repository's configured core evidence contract was satisfied. It is **not** a statement that a chip is tapeout-ready. Tapeout readiness requires the PDK/foundry-defined signoff methodology, including the appropriate corners, extraction models, DRC/LVS, reliability checks, waiver review and project-specific signoff criteria.
