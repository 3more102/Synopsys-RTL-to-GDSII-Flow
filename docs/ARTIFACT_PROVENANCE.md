# Artifact Provenance and Lineage

The flow records both run-level provenance and per-artifact lineage. Run provenance answers **which design/methodology/technology/execution identity was active**; artifact provenance answers **which stage, tool run and input fingerprints produced a specific generated file**.

## Manifest

The machine-readable manifest is:

```text
reports/provenance/artifact_manifest.json
```

Each tracked artifact may record:

```text
path
stage
required/optional class
matched contract pattern
size
SHA-256
stage runtime metadata reference
FLOW_RUN_ID
tool and tool path
stage input fingerprint
upstream stage fingerprints
stage status evidence
Git commit
run provenance digest
```

The contract defining expected artifacts lives in:

```text
config/artifact_provenance.json
```

Technology-specific or proprietary files are not guessed by this contract. Patterns describe files generated by this repository's stages.

## Stage capture

After a successful tool process, `scripts/common/run_stage.sh` writes the normal runtime metadata and then refreshes lineage for that stage. This ordering is important: the artifact manifest can point to the exact runtime record that generated the artifact.

Per-stage capture is advisory. A missing required artifact is recorded as `WARNING`; it does not silently convert a successful EDA process into a false engineering PASS or FAIL.

## Manual refresh

Refresh the complete manifest:

```bash
./artifact_provenance.sh
```

Refresh one stage while preserving existing records for other stages:

```bash
./artifact_provenance.sh --stage synthesis
```

Use the stage aliases defined by the stage graph where convenient.

## Strict gate

For release qualification or CI where the configured required outputs must exist:

```bash
./artifact_provenance.sh --strict-required
```

The command exits nonzero if a required artifact declared in `config/artifact_provenance.json` is absent. Optional artifacts never become PASS simply because they are absent; they remain unmatched optional patterns.

The strict lineage check is separate from signoff checks. Presence and checksum of a SPEF, for example, do not prove that extraction is signoff-qualified. PrimeTime timing evidence, DRC/LVS evidence and the release contract remain independent gates.

## Final delivery

`make final` refreshes artifact provenance before copying `reports/provenance/` into:

```text
final_delivery/provenance/
```

The final delivery checksum inventory therefore covers the artifact-lineage manifest as part of the auditable package.

## Security and path handling

Only regular files that resolve inside the repository root are manifested. A symlink whose resolved target escapes the repository is ignored rather than hashed or copied into provenance. This prevents an artifact pattern from accidentally recording unrelated files outside the project.
